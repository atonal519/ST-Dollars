# 百面相（Polyphony）产品设计

百面相记录人物在群像故事中的行动、结果与知情，并让玩家从故事外查看这些信息。所有人物使用同一类型，不按角色卡类别或主配角重要度分类。人物行动围绕各自目标和故事时间展开，不要求每个人都在当前正文出场。玩家能够看到作者侧记录，不代表故事中的 user 或其他人物也知道这些事。

## 当前交付与页面方向

四页方向已初步确定为当前活动、图谱、公告、设置。当前已交付图谱、人物概况、资料阅读，以及主题和模型设置；当前活动页与公告页尚未实现，新增页面的具体排版仍待确定。

- **当前活动**：呈现人物正在进行、等待或计划中的事项及已发生结果。若标记事项与故事中的 user 有关，必须有明确的故事身份及影响依据；这类关联与人物知情分开记录，不能从玩家视角推断 user 已知。
- **图谱**：呈现人物、明确关联及共同活动。当前可见的人物连线只表示明确的共同活动参与，不从位置、同场或共同参与自动推断友好、敌对等人际关系。
- **公告**：目标是把真实事件与明确传播范围转成新闻、公告或论坛表达。私密事件不会自动公开；传闻是某种说法，不等同已确认事实。此页面尚未实现。
- **设置**：当前提供跟随酒馆、日间、夜间主题，以及 Primary/Secondary 模型配置和共享 API 池引用；后续运行与历史整理入口仍待具体设计和实现。

## 数据归属与页面一致性

千千结（QQJ）是人物目录及原始状态、记忆和资料的权威来源；百面相不复制人物档案，也不另建外部人物记忆库。百面相拥有活动、已发生结果、明确知情、剧情时间与正文处理位置，并保存于自己的白鸟单条世界记录。人物世界相关页面消费从人物来源与该世界记录合成的同一个 `WorldSnapshot`，图谱与概况是它的派生展示；设置页独立读取主题与 API 设置。

正文剧情时间与主楼保持一致。计划、进行中的行动、已发生结果和人物知情各自表达：活动结果关联到明确活动，世界级事件可以独立存在；知情关联到明确人物、事件和原因。地图浏览或玩家阅读资料不会自动写成故事人物已知。

运行依赖是千千结正式公共桥、白鸟 records 接口，以及宿主现有的 chat-completions 请求接口。共享 API 池只提供被引用的连接信息；百面相按引用读取最新配置，不管理该共享池。前端常规更新通过扩展资源刷新生效，不要求增加后端服务或重启。

## 当前手动推进

用户手动点击后，百面相读取新增的已完成正文，调用一次副模型判断本轮范围，再调用一次主模型批量推演，最后一次性保存到自己的世界记录并刷新图谱。明确没有人物行动时只调用一次模型；已处理过的同一段正文不会重复推进。模型失败不自动重试。

推演保持“计划、行动、结果、知情”的边界。正文提供当前故事时点和事实依据；模型可以推进人物自己的事项，也可以产生符合人物设定的新日常，不要求人物必须出现在正文中。程序负责解析、明确身份归属及可靠保存，不替人物猜测关系或把玩家全知改写成故事内知情。

## 后续方向与未实现方案

自动推进和主楼回流仍是待实现目标，不是当前启用的行为，也不是已选定的最终策略。一个候选方向是在宿主新正文完成后推进一次，并通过独立模块把适用的世界事实注入后续正文；这项接线尚未确定。即使将来注入事实，也不代表所有人物都已知情。目标是复用宿主已有注入入口，不新增后端服务。

历史接入也是未实现能力。针对已有聊天（例如从较早楼层接入当前进度），可评估按有效正文容量分批整理已发生结果、当前未完事项、已结束事项、明确交集及来源，再将候选结果预览并按正常保存合同合并。开始前应统计正文范围、文本量和预计批次。不能逐层重演；QQJ 当前资料可以辅助理解现在，但不是过去每个时点的状态快照，也不能用现在的知识倒推过去。不得静默重置已有正文处理位置，也不能把部分相关记忆称为完整历史。接入后，日常推演仍可创作合理的新行动，而非只复述旧待办。

上述为待具体实现的产品方向，不代表已授权或已交付功能。优先建议先设计历史接入和当前活动页，再完善手动推进与主楼之间的闭环，最后实现公告表达；各阶段需要独立明确实现范围。

## 实现边界

页面与业务按职责分层：宿主适配读取 QQJ、酒馆正文和通用请求；领域模块定义人物世界与百面相拥有的状态；推演模块解析计划、结果和知情；存储模块读写单条世界记录；应用控制器装配一次推进；图谱与页面只投影、呈现同一快照。具体文件边界见[架构说明](architecture.md)。

界面优先适配手机，在同一 Shadow DOM 窗口中提供图谱、概况、完整资料和设置，并使用百面相自己的语义颜色。桌面在此基础上适配。页面切换与资料阅读不改变业务事实；业务保存只由明确操作触发。常规前端修改通过刷新生效，不依赖酒馆重启。
